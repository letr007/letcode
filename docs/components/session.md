# Session

`SessionEngine` 负责连接前端输入、会话日志、执行器、已解析路由、子代理运行时与事件输出流。`SessionEngineIngress` 接收前端无关的会话命令 `SessionCommand`，`SessionTransportEvent` 则向 TUI 或其他前端发布执行状态、恢复进度与交互事件。

## 启动与运行资源

`SessionEngine::start` 接收 Agent 实例、当前日志记录器 `TranscriptRecorder`、模型标签和会话配置 `SessionEngineConfig`，建立投影层后依次启动以下任务：

1. 配置文件变动监听器；
2. MCP 服务发现任务；
3. 会话事件主循环 `run_engine_loop`。

主循环持有 Agent、记录器、运行时目录、MCP 配置、子代理任务池以及通信通道。调用方通过 `take_ingress` 提交命令，通过 `take_event_egress` 监听事件流。会话退出时，系统先停止文件监听，再等待主循环与服务发现结束，最后清理当前工作区残留的空会话文件。

## 命令分发与活动回合

命令解析先将原始输入转换为意图。与后端相关的意图会封装为 `SessionCommand`：

- `SubmitPrompt` 进入提示词执行队列；
- `ViewChild` 与 `ViewParent` 可立即响应；
- 权限、模型、思考深度、仿真特征、快速模式和 MCP 设置在活动回合中暂存为延迟设置；同类设置以后一次为准，并在当前回合完成后生效；
- `DelegateSubagent`、手动压缩、历史导航、撤销重做及会话切换等命令，若在活动回合中触发，会依序拒绝、推迟或给出提示；
- `Interrupt` 通过独立中断通道请求取消当前操作。

## 路由解析与权威安装

会话引擎不会把配置文件中的原始 `ModelRoute` 直接传给网络层。模型切换、状态恢复和配置重载均需通过路由工厂生成 `PreparedPrimaryRoute`。该阶段会校验服务商、协议类型、元数据、重试配置与运行时环境，确认无误后在提交点安装。

安装后的 `Agent::resolved_model_route` 是当前会话的唯一权威路由。普通回合、压缩辅助调用、子代理回合及其他模型请求均使用该路由或其派生路由。`active_protocol` 仅用于状态显示与兼容性检查，实际请求准备均由已解析路由的协议绑定完成。

恢复会话时，`prepare_restored_model_route` 依据日志中记录的最新模型重新解析。若模型依然在当前配置中，则提交完整的预备路由；若只能恢复模型名称，则保留标识，并由当前 Agent 默认路由提供执行权威。安装前系统会再次校验路由、快照、上下文作用域与权限状态。

## 配置热重载

监听器合并短时间内的多次变动通知，随后调用 `apply_config_reload`。热重载会重新解析并验证配置，刷新运行时目录、模型清单、路由工厂、API 密钥提示、重试策略、上下文压缩与工具并发控制。

系统通过比对以下状态决定如何应用变更：

- 运行时目录的数字指纹；
- 模型与专家的默认路由映射；
- Agent 重试、压缩、超时与工具并发配置；
- 当前活跃路由对应的运行时指纹；
- 新会话的默认路由。

若配置未发生实质变化，系统保持当前状态不变。若当前路由对应的环境或配置发生改变，热重载会先解析新路由再完成替换。若当前路由已从配置文件中删除，已存在的会话继续保留当前正在使用的路由，并通过通知提示用户，不会强行切换为新默认模型。新默认路由仅对后续新建的会话生效。若新配置文件格式错误或校验失败，系统保留原运行状态，并向前端发送错误事件。

## 回合执行流程

提示词执行由 `AgentRunner::run_prompt` 或支持自动继续的 `run_prompt_with_continuations` 负责。记录器为 Agent 提供运行时快照投影，投影基于当前日志与上下文分支构建。

单个提示词回合在会话侧的执行顺序如下：

1. 发出 `UserMessage` 用户输入事件；
2. 将用户内容写入记录器，并发布上下文更新；
3. 在首次交互时生成并保存会话标题；
4. 调用 Agent 的 `run_stream_content_with_interactions_async` 发起流式执行；
5. 将内部 `AgentEvent` 写入日志文件，并转换为前端传输事件；
6. 成功完成时发布上下文更新、`AssistantDone` 与 `Done` 事件；
7. 遇到失败或中断时记录错误状态，并发布 `Error` 与 `Done` 事件。

助手文本增量、思考过程、工具生命周期、Token 用量、上下文压缩、重试、待办事项、权限审批与交互式问题，均统一通过 `SessionTransportEvent` 发布。审批与提问事件带有一次性响应句柄。

后台子代理任务完成后，引擎接收 `BackgroundSubagentCompleted` 通知，将执行结果归档为主会话证据，并将后续处理指令重新推入控制队列。

## 会话恢复与切换

恢复会话时，系统先解析会话 ID 或前缀，再通过 `prepare_resume_package` 准备恢复包：

1. 读取会话 JSONL 文件并校验文件指纹；
2. 解析当前分支、叶节点与运行时快照，同时发现该会话的子代理记录；
3. 获取目标会话文件的跨进程独占文件锁，在锁内确认指纹匹配且事务完整；若目标会话已被其他实例持有，直接拒绝恢复；
4. 将记录器挂载到选定分支，并重建上下文作用域；
5. 若快照中存在未完成的回合，取消挂起的工具与子代理，写入 `TurnInterrupted` 记录并重新构建快照；
6. 返回包含会话 ID、记录集合、运行时快照与记录器的准备对象。

提交过程是一次严格校验的会话切换。系统先验证恢复快照与预备路由，再替换活动记录器，安装运行时快照、回合序号、作用域、权限与已解析路由，最后清理先前产生的空会话文件。操作成功后对外发布 `SessionResumed`。若校验失败，原有会话状态不会被损坏。

系统支持直接读取 journal schema 1 与 schema 2 格式的日志。读取 schema 1 时，系统在内存中将旧版助手输出转换为 `AssistantTurn` 格式，原文件不作修改，后续新内容使用 schema 2 写入。更早且不含封套的旧日志仅用于展示与检索，不再恢复为活动会话。

## 分支导航与子视图

运行时快照根据当前游标、最近迁出点或根分支解析内容路径。系统合并父分支与本地记录，恢复运行时帧、历史、上下文节点、审计证据与子代理摘要。其他平行分支的内容不会混入当前视图。

撤销、重做和分支切换通过 `HistoryNavigation` 事件记录目标序列号与重做栈，不修改已经持久化的历史记录。`ViewChild` 与 `ViewParent` 仅用于切换查看视角，不会把查看对象设为主活动会话。

## 会话索引

`src/transcript/session_index.rs` 维护磁盘文件 `sessions-index.json`。系统根据文件大小与修改时间判断索引是否过期。索引损坏或过期时，仅重新扫描发生变化的 JSONL 文件。扫描能够识别当前格式及旧版日志，提取记录条数、时间范围、模型名称、标题与最近对话摘要。该索引仅用于展示会话列表，不参与会话恢复的合法性校验。

## 源码索引

- `src/session/engine.rs`：实现会话引擎生命周期、命令处理循环与事件分发。
- `src/session/engine/config_reload.rs`：处理配置热重载、指纹比对与路由重装逻辑。
- `src/session/runner.rs`：调度回合执行，转换内部事件并接收子代理事件。
- `src/session/restore.rs`：构建恢复数据包，校验路由并完成会话切换。
- `src/session/lifecycle.rs`：管理会话文件路径，提供安全的记录器打开机制。
- `src/session/settings.rs`：执行路由准备，安装权威路由并应用会话配置。
- `src/transcript/journal.rs`：处理日志封套、校验模式门禁与文件指纹。
- `src/transcript/session_index.rs`：维护磁盘会话发现索引。
